# 0051 Another class's bars laid out from Rob's druid bars

## Why

Rob, 2026-09-24: "use the druid setup and layouts to setup all the other classes". Bellular's system
(clippings "Make Midnight More Fun TODAY: Our New Foolproof Keybinding System" and "Midnight
Keybinding Planner") puts each ability in a category, and gives each category the same key in
every spec, so muscle memory carries across. Rob's own keys play the part of Bellular's.

## What is known

- Bellular's planner is a public Google Sheet, `1czh-ldWbTuNJbsxpzmzDG9iCO3YSVDlqafuUzbuQlJ4`. It
  downloads as CSV with no sign-in: `.../export?format=csv&gid=<gid>`.
- **Master Sheet, gid 570501571**: columns `Bar, Slot, Keybind, Category`, then one column per
  spec (all 39). Each row is a category and its ability in each spec. For example, `Combat 1` is
  Heart Strike (Blood), Shred (Feral) and Mangle (Guardian); `Combat 5` is Death Strike (Blood)
  and Tiger's Fury (Feral). Rows also cover defensives, movement, CC, utility and items.
- Per-class sheets exist too (Druid is gid 815175565), with the same rows.
- Rob's druid layouts are already saved per spec (`db().bars`, card `0033`). Keys are bound to
  buttons (`ACTIONBUTTON1` and so on), not to spells, so they carry over by themselves. Only the
  abilities on the buttons need translating.
- **Prior work: `C:\Dev\WoWAddons\DjinnisClassProfiles`** saves and restores bar layouts as named
  profiles per class. Read its handover before building, and reuse or retire it rather than
  building a second copy (`php C:\Dev\ProgressBoard\artisan board:map wow`).

## What

- **The template is the druid spec of the same role** (`0048`, decided): melee DPS copy Feral,
  ranged DPS copy Balance, tanks copy Guardian, healers copy Resto.
- **Feral first, then the other druid specs.** Rob, 2026-09-24: Feral's bars have "a LOT of work"
  that Balance, Guardian and Resto do not yet have, and Resto is his least developed layout. So the
  first run is Feral to his own Balance, Guardian and Resto, through the same translation. It tests
  the translation on specs he knows, and makes the three templates good before other classes copy
  them. He previews and keeps or discards each one, as with any layout.
- A translation table from the Master Sheet, kept in the addon: spec -> ability name -> category,
  and category -> ability per spec. Generated by a script, as the builds are.
- For a target spec: take the template druid layout (`0048` question 1). For each button, find the
  druid ability's category, and put the target spec's ability for that category on the same
  button.
- **Match by button, not slot.** A druid's combat buttons sit on form pages (Cat is slots 73 to
  84). Another class has them on slots 1 to 12. Each druid form page maps to the button it shows
  on.
- An ability the character does not know, a druid-only action with no category (forms, Prowl),
  and a category the target spec leaves empty: the button is left empty and listed.
- The result is a normal saved layout for that spec. So the ghost preview (card `0046`), Load and
  Undo all work on it unchanged, and Rob sees it on his real bars before loading.

  brackets. "A/B" stays: the first one the character knows is used.

  - Items, pets and mounts carry over. A druid macro or flyout carries only to a druid.
  - Another class's pages 73-120 (a rogue's stealth bar) are left as they are now.
